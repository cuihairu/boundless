# Mercury 线格式逐字段解码（登录段,会话 59631,2026-11-24 21:36）

字节序总则(实证):`lib/cstdmf/binary_stream.ipp` 的字节序宏在非 BIG_ENDIAN 主机上是
恒等宏(`#define BW_HTONS( x ) x`,`BW_NTOHS = BW_HTONS`),因此本机 x86 el7 构建的
Mercury 包头/消息头整数字段一律**主机字节序(小端)上线**。下列全部按 LE 解,逐包字段
自洽、请求号跨包连续,验证该结论。

包结构:`[flags u16][消息流...][footer 区,从包尾向消息区反向排布]`
flags 位定义(lib/network/packet.hpp:62-71):
  0x0001 HAS_REQUESTS      0x0002 HAS_PIGGYBACKS   0x0004 HAS_ACKS
  0x0008 ON_CHANNEL        0x0010 IS_RELIABLE      0x0020 IS_FRAGMENT
  0x0040 HAS_SEQUENCE_NUMBER 0x0080 INDEXED_CHANNEL 0x0100 HAS_CHECKSUM
  0x0200 CREATE_CHANNEL    0x0400 HAS_CUMULATIVE_ACK

消息头(lib/network/interface_element.cpp:103-118, 517-560; udp_bundle_processor.cpp:400-490):
  定长消息:  [id u8][payload 固定长]
  变长消息:  [id u8][len u16 LE][payload]
  请求消息:  头部之后跟 [replyID u32 LE][nextRequestOffset u16 LE],再接 payload
  回复消息:  [0xFF][len u32 LE][replyID u32 LE][payload],len 覆盖 replyID+payload
  id=0xFF 即 REPLY_MESSAGE_IDENTIFIER(interface_element.hpp:342)
消息 ID 分配(interface_minder.cpp:34 `MessageID id = elements_.size()`):按接口内声明
序 0 起。LoginInterface(lib/connection/login_interface.hpp:52-60):
  login=0  probe=1  challengeResponse=2
BaseAppExtInterface(lib/connection/baseapp_ext_interface.hpp:27-31):
  baseAppLogin=0(定长 5B:SessionKey u32 + numAttempts u8,basictypes.hpp:171)
  authenticate=1 ...

  msgID        = 0x00 LoginInterface::login(变长)
  len          = 0x0104 = 260(LE)

  nextRequestOffset = 0
  payload[0..3]  = 00 00 09 02 → LE u32 = 0x02090000 = 协议版本 2.9.0

                   startRequest( LoginInterface::login ... );末字节 2e 属密文)
  包尾 2B       = firstRequestOffset footer = 0x0002(HAS_REQUESTS 时反向打包,
                   udp_bundle.cpp:561-564)
  字节账:2+3+4+2+260+2 = 273 ✓ 完全闭合
