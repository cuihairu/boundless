## 端口语义

- **每连接类型注册表**：`register_entity_type(type_id, &schema)` +
  `schema_of(type_id)`（= 参照 `entityTypeMappings_`，端口为连接内存态，
  测试里读写双方各自注册）。未注册类型各操作结局照契约：get → `Ok(None)`、
  put → `Storage("entity type {} is invalid")`（XML 后端文案）、
  del/check_out → `NotFound`；logon_of/check_in 不设类型门（固定表按
  type_id 查询，未注册类型自然无行）。
- **`RefCell<Client>`**：`postgres::Client` 方法要 `&mut self`，契约读方法
  是 `&self`——`client: RefCell<Client>` + `client_mut() -> RefMut<'_, Client>`
  提供内部可变性；调用点（含各集成测试）对实参形一律 `&mut x.client_mut()`
  重借（clippy `explicit_auto_deref` 裁定 `&mut` 形）。
- **put 三腿**（`impl EntityStorage for PostgresStorage::put_entity(key,
  values, put_explicit_id)`）：
  - `db_id == PENDING_DATABASE_ID` → 固有 `create_entity`（06-04 的表序列
    `RETURNING "id"` 分配腿）；
  - `put_explicit_id` → `insert_explicit_entity_sql`：**裸 INSERT** 带 id 列。
    列为 `GENERATED BY DEFAULT`，显式 id 按普通值绑定；重复 id 撞主键，
    经 `map_write_error` → `AlreadyExists`，原行存活（语句无 `ON CONFLICT`，
    单测逐字钉死）；**序列不动**（见下登记）；
  - 其余 → update 腿：`row_exists_sql` 先查（upsert 会把缺行写成新行），
    缺行 `NotFound`，否则 `put_entity_sql` 的 `ON CONFLICT ("id") DO UPDATE`。
- **del**：`DELETE` 受影响 0 行 → `NotFound` **且不碰** LogOn 记录
  （del_entity_task.cpp:69-74）；成功则无条件 `remove_logon_sql`。
- **LogOn 面**（固定表 `bigworldLogOns`，DDL 在 `schema_init::plan()`）：
  `put_logon_record`（公有裸面 = `addLogOnRecord`）、`logon_of`
  （`get_logon_sql`）、`check_out`（行缺 → `NotFound`；已被占用 →
  `CheckOut::Elsewhere(holder)`；否则写登记记录返回 `Granted`）、
  `check_in`（无条件 `DELETE`，释放空座也行）。
  ip/port 落库走网络字节序：`stored_ip`/`stored_port`（htonl/htons）
  进、`read_ip`/`read_port`（ntohl/ntohs）出——`swap_bytes`，且 port 须先
  截 u16 再换（`i32 as u16` 后 swap；i16 换会坏 >32767 的端口）；salt 整宽
  存取（`stored_salt`/`read_salt` 直通）。
- **all_entities**：逐注册类型 `select_all_entity_sql` 扫表，行序按
  (type_id, db_id) 全序排定（契约要求确定序）。

## 与旧交付（fe41751）的差异——登记分歧

- **分配模型归并账**：main 已选表序列分配（a289d8d，`GENERATED BY DEFAULT
  AS IDENTITY`）。显式写为裸 INSERT，**不**做 `bump_identity`
  （`setval(GREATEST(...))`）、**不**带 `OVERRIDING SYSTEM VALUE`——被拒的
  显式写不再烧序列号，id 序列里没有旧稿那个不可见空洞。代价：显式 id 不推
  进序列，造 id 与显式 id 可能撞——这正是 BW-09-07-06 导入校准
  （`setval(pg_get_serial_sequence, max+1, false)`）的活，`dbid.rs` 的
  `an_explicit_id_does_not_advance_the_sequence` 一例已把该行为钉在 main 形状。
- **注册表漂移故障面**：旧稿有 drift/缺表专用故障用例；重交后漂移同样落
  `map_db_error`/`map_write_error` 的通用故障臂（`check_row_width` 宽度守卫），
  不再单设用例。
- **契约用例收紧为 9 例**（旧 17 例）：挑契约面（三腿、NotFound 簇、
  Granted/Elsewhere/释放、字节序、全序、删除连带登记记录），跨连接可见性类
  用例不重设（真库无连接私有态，dbid.rs 的并发例已覆盖该面）。
